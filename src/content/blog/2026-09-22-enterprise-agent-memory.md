我现在越来越不相信“上下文窗口再长一点，企业 Agent 的记忆问题就会解决”。企业真正缺的不是把更多文件一次塞给模型，而是把十几年业务里分散、冲突、会更新的事实，整理成一套能追溯来源、能被长期复用的机构记忆。

9 月 21 日，OpenAI 发布了一篇 V7 的客户案例。V7 Go 把 SharePoint、Google Drive、数据室、表格和其他内部资料里的实体、关系、事实和指标整理到 Context Graph，再通过 MCP 给 Agent 查询。OpenAI 的案例里，V7 报告 GPT-6 Astra 在其最困难的一组图查询上达到 89% 准确率；V7 还声称，图结构检索在 HERB benchmark 上比官方 baseline 高 69%，并让无法回答的问题少出现一部分幻觉。

这些数字主要来自 V7 自己，不能直接当成行业结论。但它指向的产品判断很值得讨论：企业 Agent 的瓶颈正在从“模型不会推理”转向“模型不知道公司到底发生过什么”。

市场最容易的误读是：1M token、2M token 甚至更长 context 出来以后，RAG 和 memory 都会变得没必要。

我觉得恰好相反。

第一，企业知识的问题不是“太长”，而是“太乱”。

同一家客户可能在 CRM 里叫一个名字，在合同里用法律实体名，在邮件里又是简称；一个基金季度报告可能后来被重述；一个项目状态在 Slack、会议纪要和项目管理系统里都有不同版本。把这些东西直接塞进长上下文，模型仍然要现场解决实体对齐、时间先后和来源冲突。

Context Graph 试图提前做的是“把关系整理好”：这家公司是谁、这份报告属于哪一期、某个数字来自哪份原始文件。真正的价值不是图数据库三个字，而是把企业语义从每一次推理任务里拿出来，变成可重复使用的公共资产。

第二，长期 Agent 会让“重新搜索一遍”越来越贵。

一个只回答一次问题的 chatbot，做十次搜索没有太大问题。一个每天运行、一次要走 50 到 100 个步骤的 Agent，如果每次都从头找“这个客户是谁”“上一版合同是什么”“哪个指标已经更新”，token、延迟和错误概率都会累积。

V7 的做法是把最近交互留在 active context，把较旧信息放进外部记忆，需要时再检索。这个设计很普通，但我觉得它比“永远扩大上下文”更接近工程现实。

因为企业历史是持续增长的。哪怕模型今天有 1M token，公司的十年邮件、文件、会议和交易记录也会远远超过它。

第三，机构记忆的真正门槛是 provenance，而不是 recall。

企业里最危险的回答往往不是“没搜到”，而是“搜到了一个已经失效的版本”。如果 Agent 要做投资筛选、保险核保、合同审核，答案必须能回到原始证据：这个数字来自哪份报告，这个条款是谁在什么时候改的。

这也是我觉得 source-linked memory 比普通向量库更重要的地方。Memory 不应该只有结论，还要带来源、时间和版本。

HERB benchmark 给了一个很好的背景。Salesforce AI Research 构造了 39,190 个异构企业 artifact，包括文档、会议、Slack、GitHub 和网页。论文里最好的 agentic RAG 方法平均得分也只有 32.96，作者把 retrieval 识别为主要瓶颈。这个结果是一年前的研究，不能说明今天所有系统都还这么差，但它至少证明“企业检索很难”不是营销部门制造出来的问题。

第四，如果机构记忆成立，企业 Agent 的竞争方式会变。

今天大家很容易比较“谁部署了更多 Agent”。但如果十个 Agent 都在重复建立自己的上下文，数量越多，成本可能越高，错误还可能互相不一致。真正高效的架构可能是多个 Agent 共享同一套受控记忆，再根据权限访问不同部分。

这样一来，企业 AI 平台最有价值的资产可能不是 Agent 数量，而是：统一实体、历史决策、来源证据、权限和更新机制。

## 风险在哪

我最担心的第一件事，是“机构记忆”把错误固化。

普通 RAG 搜错一次，只影响一次回答；如果 Context Graph 在实体合并时把两家公司认成同一家，错误可能被几十个 Agent 长期复用。越是持久化的 memory，越需要版本、置信度、冲突处理和重新验证。

第二，图结构不一定天然优于现代长上下文和检索模型。很多企业数据变化极快，提前建立 ontology 和实体关系的维护成本可能很高。对于资料量不大、任务简单的团队，直接搜索原文可能更便宜。

第三，V7 的案例数字来自厂商测试。99.9% workflow accuracy、21 倍速度等宣传性结果，需要在不同企业、不同数据质量下独立复现。一个在私募和保险资料上很好用的 Context Graph，不一定在制造现场、研发代码或客服知识里同样成立。

什么证据会推翻我的判断？如果接下来更长上下文模型在真实企业多源任务里，直接读取原始资料就能以更低成本达到同样准确率，而且不需要长期维护结构化记忆，那 Context Graph 这类中间层的价值会明显下降。

我下一步最想查的是：V7 在 HERB 上的完整评测配置和绝对分数；Context Graph 出现实体冲突时怎么修正；一条事实更新后有多少旧分析能被自动标记为过期；以及共享记忆怎样和员工权限系统结合。企业 Agent 真正成熟的标志，可能不是“它记得更多”，而是“它知道自己记住的东西从哪来、什么时候可能已经不对”。
