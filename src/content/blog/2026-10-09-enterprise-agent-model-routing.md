我觉得 10 月 8 日 Google 新发布的企业 Gemini agent，有一个细节可能比产品名字更重要：它可以在自己的 Agent 系统里使用 Anthropic 的 Claude。模型供应商开始主动把竞争对手的模型放进工作平台，意味着竞争的单位正在改变。以后谁能留住企业，未必取决于自己训练的模型是否每次都排第一。

Google Cloud 官方解释得很直白：Gemini agent 是负责工作目标、工具、技能、记忆和权限的执行系统，底下具体用哪个模型可以另选。它目前支持 Gemini 和 Claude，未来计划兼容更多专有模型和开放模型，还提供任务级选择与成本控制。Reuters 和 VentureBeat 在 10 月 8 日的报道中确认了这一产品方向，同时指出它目前只向部分企业客户开放预览，真正的成本和跨模型数据规则仍有细节待说明。

很多人看到这条新闻会说：“模型要商品化了，谁都能换，所以大模型不再有壁垒。”我不太同意这样跳结论。前沿模型的可靠性、工具使用、安全表现和特定专业能力依然有差异。发生变化的是：**企业可能开始把模型视为可选择的计算资源，而把长期工作能力留在上层系统。**

## 为什么现在开始允许“用别人的模型”

如果企业只让大模型回答一次问题，用最强模型往往是个简单选择。但长任务不是这样。一个 Agent 可能要读取十份材料、检索数据库、筛选信息、写代码、执行验证，再整理输出。任务里的每个步骤对模型能力要求差异很大。

假如所有步骤都调用同一款昂贵模型，费用和延迟会不断累积；假如全部交给廉价模型，关键节点又可能失败。Google 在官方发布中强调 Smart Routing 和实时支出上限，正是在承认这个现实：企业衡量的不是一次回答多聪明，而是**一定预算之内完成了多少可以验收的工作**。

这里会产生一层新的软件价值：调度器需要判断何时使用高能力模型，何时交给低成本模型，何时用代码或者传统 SQL 直接完成。它还需要知道一次失败是否值得重试，以及重试换模型后是否真有改善。这个决策如果做不好，“多模型支持”只是菜单里多几个名字；如果做得好，才有机会形成持续的成本优势。

但我认为更大的变化在于记忆和工具并不跟着模型一起更换。Google 把 session、semantic、procedural、episodic 等不同记忆留在自己的 Agent 系统里，工具与技能也有独立注册机制。这样底层今天用 Gemini、明天用 Claude，企业的任务历史和操作流程原则上仍可延续。

换句话说，真正被保护起来的资产变成了：某家公司怎么做采购、怎么批准费用、怎么处理异常、某条报表口径为何这样定义。模型只是暂时参与其中的推理引擎。这有利于企业减少被单一模型版本绑定，但也可能把依赖从模型层迁移到 Agent 平台层。

## “模型可替换”未必等于“厂商可替换”

这是我最担心的误读。

如果一个平台提供开放的模型选择，但所有记忆、权限、工具注册和执行日志都保存在自己定义的系统里，企业切换模型可能容易，切换平台却更困难。更进一步，同一个业务任务使用不同模型时，工具调用格式、结构化输出稳定性、推理时延与失败类型都可能变化，不能只改一下模型名称就认为质量不受影响。

Google 提到将第三方模型纳入治理系统。VentureBeat 的报道也指出，有关第三方推理时数据传输、保留和驻留安排，公开信息仍不足以做完整判断。这是选型必须追问的地方：公司承诺“数据留在平台里”，究竟指业务存储不迁移，还是每一次推理都不向外部服务发送敏感上下文？两者不是同一个问题。

在企业环境里，审计也有类似细节。一个审批 Agent 先用低成本模型总结合同，再用高能力模型识别风险，最后用另一套程序提交审批。后续如果发现错误，要能追溯当时调用了哪个模型版本、输入了哪些经过脱敏的事实、是谁设定了路由策略，而不只是记录“Agent 完成了一次任务”。

这会把模型路由从单纯的价格算法，推向带有合规和可解释要求的生产系统。它需要成本指标，也需要任务成功率、风险分类和错误归因。

## 我可能错在哪

首先，不排除垂直领域最终会出现一个模型明显更适合某类任务，企业为了一致性反而主动减少模型数量。复杂的路由本身也是软件，有配置错误、状态不一致和额外维护成本。对任务量很小的团队，买一款足够好的模型，可能远比搭建调度器划算。

其次，Google 的跨模型机制目前处于预览阶段。官方展示了架构方向和部分客户案例，却尚不足以证明它在严格的同任务、同预算条件下，比固定单模型方案有多大净收益。即使 token 费用下降，如果新增重试、验证和人工复核，实际成功任务成本仍可能上升。

还有一种可能：模型厂商自己会不断强化内置工具和工作空间，最终重新把上层执行系统整合回模型产品。那时调度权也许不像我想象中那么稳定。

下一步我最想查的是一项可复现实验：选一组有明确验收标准的企业长任务，分别用固定单模型、按步骤手工选模型、自动路由三种方式运行，记录端到端成功率、总成本、人工复核次数、完成时间和数据流向。只有把这些账算清楚，才能知道“开放模型选择”究竟是产品卖点，还是企业愿意长期付费的软件能力。
