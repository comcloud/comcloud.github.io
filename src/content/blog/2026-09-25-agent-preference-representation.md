我越来越觉得，Agent 进入真实市场以后，第一道难题不是“会不会谈判”，而是“它到底能不能准确代表你”。如果一开始就理解错了你的偏好，后面越会协商，越可能把错误执行得更漂亮。

Anthropic 9 月 24 日发布 Project Swap：201 名员工先和 Claude 做一段简短交流，再让各自的 Agent 进入一个数字交易场，替他们交换书。研究者另外收集参与者自己的书籍排序，用来判断 Agent 是否真的理解了人。

最容易被传播的说法是：Agent 已经开始替人砍价和交易。这个说法没错，但我觉得它抓错了重点。实验里，Claude 根据短聊生成的排序，与参与者自己的排序在成对比较上只有 61% 一致。按参与者真实偏好计算，最理想分配的效率约为 0.89，实际交易约为 0.55。Anthropic 再做分解后发现，大部分损失并不是 Agent 在交易桌上谈得差，而是它一开始没有把人的偏好理解准。

这件事让我重新看个人 Agent 的产品路线。

## 真正稀缺的，可能是“代表能力”

今天很多 Agent 产品都在强调执行：能搜索、能比较、能联系、能下单、能和另一个 Agent 交流。于是我们很自然地把“能力更强”理解成“更会替我做决定”。

但这两件事不是一回事。

一个人说“我想看点轻松的”，里面可能藏着很多没有说出口的条件：不要太长、不要已经看过、最近不想读某一类题材、希望有一点新鲜感但又不要太陌生。Agent 如果只抓到一句表面要求，后面的所有优化都会建立在不完整的目标上。

Project Swap 里有个很有意思的细节：参与者在最初交流中提供的信息越多，Agent 对偏好的匹配通常越好。这说明模型能力之外，还有一个很朴素的问题——用户究竟愿意花多少时间，把自己的偏好讲清楚。

所以我怀疑，未来个人 Agent 很重要的一层产品能力，不是再多接几个工具，而是把“理解用户”做成持续过程。它需要知道哪些偏好长期稳定，哪些只是这周有效，哪些信息已经过时，哪些地方自己其实没有把握。

## Memory 会有用，但 Memory 也会制造旧偏好

很多人会说，这个问题最后会被长期记忆解决。Agent 用得越久，知道得越多，自然就更懂你。

我只同意一半。

偏好不是静态配置。去年喜欢的东西，今年可能已经没兴趣；某次选择是因为当时特殊情况，不代表以后都应该照着做。如果 Memory 只负责积累，而不负责重新验证，它可能把偶然选择固化成长期规则。

这会形成一种很难察觉的偏差：Agent 看起来越来越懂你，实际上越来越懂“过去的你”。

所以真正高质量的记忆系统可能需要三个动作：保存、衰减、复核。它不是简单记住更多，而是知道什么时候应该忘，什么时候应该重新问。

## 市场可能需要一种新的“代表能力测试”

Anthropic 在研究讨论里提出一个很实际的方向：在 Agent 真正出去行动之前，先让它做几道样例决策，再让用户判断这些选择是否像自己。

我觉得这个设计可能比很多炫目的 Agent Demo 更接近真实产品。

今天软件授权通常只检查“它能做什么”：能不能读文件、能不能访问网站、能不能调用某个服务。以后还可能多一个问题：它是否已经足够理解这个人，适合自己做决定。

比如一个图书 Agent 可以先给出十本书的排序；旅行 Agent 可以先在几组行程之间做选择；内容 Agent 可以先判断哪些文章用户愿意读。只要这些样例和用户真实判断差距很大，就说明 Agent 还不适合获得更大自主权。

这会催生一层新的基础设施：偏好校准、决策回放、用户修正、错误归因。一个 Agent 不是因为模型版本够新就自动获得信任，而是因为它在具体用户身上通过了一次又一次小测试。

## 更强模型也许会变成“代理质量差距”

Project Swap 还有一个信号：按 Claude 自己构建的偏好衡量，使用更强模型的交易场整体更有效率。在混合模型环境里，强模型代理通常也占一些优势。

这还远远不能推出真实世界会形成“有钱人用强 Agent，其他人用弱 Agent”的结论。毕竟实验只是换书，而且参与者都来自 Anthropic。但它提出一个值得继续追踪的问题：以后模型差距会不会表现为代理质量差距？

如果弱 Agent 更容易误解偏好、过早妥协或遗漏更好的交换机会，那么模型价格差异就不再只是“响应快一点、回答好一点”，而是可能直接影响最终选择质量。

我现在还不敢下结论，因为实验里用参与者真实排序衡量时，不同设计之间的差距没有想象中那么大。但这是一个可以被现实数据验证的问题。

## 风险在哪

Project Swap 的限制很明显。参与者是 Anthropic 员工，本来就比普通用户更熟悉、也可能更信任 Claude；交易的是书，失败成本很低；所有 Agent 都是相对合作的，没有专门设计恶意对手；最终问卷也不是所有人都填写。

所以我可能错在高估“偏好理解”在真实 Agent 市场里的重要性。进入更复杂的市场后，对手欺骗、规则设计、身份验证、履约失败，都可能比偏好误差更重要。

还有一种可能是，用户根本不愿意花时间校准 Agent。理论上增加更多交流能提高理解准确度，但如果每次使用前都要做一轮长访谈，Agent 的便利性就消失了。

## 下一步去查什么

下一步我最想看到的是一类真实产品数据：一次 Agent 决策失败，到底有多少来自“理解错用户”，多少来自“搜索不全”，多少来自“协商失误”，多少来自“执行错误”。

只有把失败拆开，我们才知道该继续堆模型能力，还是应该把更多产品资源放在偏好校准、记忆更新和决策回放上。

如果未来半年有任何消费型 Agent 开始公开这种错误分解，我会优先看它，而不是再看一轮谁的 Agent benchmark 排第一。
