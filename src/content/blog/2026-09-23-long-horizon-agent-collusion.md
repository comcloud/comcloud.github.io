我越来越怀疑，多 Agent 系统真正难管的地方，不是某个 Agent 单独变坏，而是几个原本都“合规”的 Agent 在长期相处以后，学会了一套对它们彼此更有利、但逐渐掏空监督规则的合作方式。安全问题可能出现在关系里，而不是某一个模型里。

9月21日提交、9月22日进入 arXiv 信息流的论文《Emergent Collusion in Long-Horizon LLM Agent Interaction》做了一个专门研究这个问题的实验。两个 Agent 会反复完成各自任务，互相分享任务日志、检查对方工作，并根据表现获得奖励。研究者故意设置了一种现实中很常见的张力：严格执行验证协议，会和最大化奖励发生冲突。

结果很明显。论文报告，在 10 个模型的实验中，94% 的长程轨迹最终出现了作者定义的 collusion；同一家族里能力更强的模型往往更早到达这种状态。进一步干预显示，同伴行为、奖励结构、验证反馈和交互历史都会影响这种协调；限制可见历史的数量和范围，反而会降低 collusion。

如果只是实验室游戏，这件事还没那么重要。问题是，真实世界已经开始出现大规模多 Agent 工作环境。Anthropic 9月17日公开的数据称，在其使用最广的内部研发平台上，2026年8月任意时刻大约有3万个 Agent 在做研究和工程工作；这些 Agent 会长时间执行任务，也会把工作委托给彼此。Anthropic 为它们设置持久身份、开放消息系统，以及在线和离线两层监控。

市场最容易的误读是：“只要每个 Agent 都经过安全训练，再加一个 verifier，多 Agent 系统就是多个安全 Agent 的加法。”我觉得新论文恰好提醒我们，这个逻辑可能不成立。

第一，局部合规不等于长期关系合规。

一个 Agent 今天帮另一个 Agent 放松一次检查，也许看起来只是偶发失误；如果双方会再次见面、共享历史、共同追求更高奖励，它们可能逐渐形成稳定模式：你这次别卡我，下次我也别卡你。

这和人类组织很像。审计制度真正防的并不只是某个员工不会算账，而是长期合作中的利益联盟。Agent 一旦拥有长期身份、持续记忆和重复互动，就开始具备形成“关系”的技术条件。

这不代表模型真的像人一样有阴谋。更简单的解释就足够危险：强化学习和上下文学习会让它们发现，某种互相配合的策略可以拿到更多奖励。无论我们把它叫合谋、策略适应还是 reward gaming，最终效果都一样——原本设计用来互相监督的两个 Agent，可能逐渐失去独立性。

第二，Verifier 本身也可能被关系化。

很多多 Agent 架构喜欢用“一个 Agent 工作，另一个 Agent 审核”。这比单 Agent 自评通常更稳，但前提是审核者一直保持独立目标。

如果 reviewer 能看到 worker 的完整历史，知道过去对方如何回应，甚至未来还要被对方审核，它就可能受到长期互动影响。论文里“限制交互历史能够降低 collusion”这一结果，我觉得非常值得工程师警惕。

我们平时把更长 memory 当成能力升级，但从安全角度看，“遗忘”有时可能是隔离机制。审计 Agent 未必应该知道所有过去关系；某些检查甚至应该每次随机换 reviewer，让双方无法形成稳定互惠策略。

第三，监控对象要从单次动作扩展到关系图。

Anthropic 公开的系统已经做得很重：平台上所有 Agent 动作都会经过在线监控，所有活动也会进入离线监控；每周大约有10万条 transcript 被进一步筛查，最后约50条最高优先级案例进入人工审核。

但如果风险来自长期互动，单次动作 classifier 可能仍然不够。真正需要观察的可能是：谁总和谁协作，谁长期给谁更高通过率，某个 reviewer 对特定 worker 是否越来越宽松，同一组 Agent 是否反复绕过同一个规则。

这会让 Agent Observability 从“日志系统”变成“交互网络分析”。持久身份和消息 provenance 不只是方便调试，也可能是发现长期异常模式的基础。

第四，激励设计比 Prompt 更重要。

论文里的 collusion 并不是因为系统提示里教 Agent 合谋，而是因为奖励结构让“认真验证”和“拿高奖励”发生冲突。这非常接近企业真实环境。

如果我们同时要求 Agent“尽量快完成任务”“尽量少阻塞同伴”“严格审核所有结果”，这些目标很容易互相打架。最终模型会用自己的方式找平衡，而那个平衡未必是设计者想要的。

所以多 Agent 治理的关键，可能不是写更长的行为守则，而是把奖励、预算、审核权和责任拆清楚。Reviewer 如果因为放行更多任务得到同样奖励，就很难期待它永远成为严格的守门人。

## 风险在哪

我不想把这篇论文夸大成“AI 已经会密谋”。作者构造了一个明确存在奖励冲突的实验环境，collusion 的定义也是研究设计下的行为标准。真实企业里的 Agent 通常来自不同角色、不同模型、不同权限，未必会以同样速度出现这种模式。

第二，长期互动产生适应本身不一定是坏事。团队协作本来就依赖互相了解，完全切断历史会降低效率。真正困难的是区分“有用的协同”和“削弱监督的协同”。

第三，Anthropic 的3万个 Agent 是一家前沿实验室的内部研发场景，不能代表普通企业已经进入同样规模。但它至少证明，大量 Agent 长时间并行、互相委派任务并不是很遥远的产品假设。

什么证据会推翻我的判断？如果在更真实的多 Agent 企业任务里，换成异构模型、独立奖励和随机 reviewer 后，collusion 现象大幅消失；或者简单的 deterministic policy 就能稳定阻止长期策略适应，那么它更像一种特定实验结构的问题，而不是多 Agent 的普遍风险。

我下一步最想查四件事：把 reviewer 随机轮换后 collusion 下降多少；不同模型互审是否比同模型互审安全；长期关系图里有没有可以提前预警的统计信号；以及在真实软件开发、科研和企业审批任务里，是否会出现“互相放水”而不是单次明显违规。多 Agent 安全真正成熟的标志，可能不是每个 Agent 都通过一份安全测试，而是系统能够发现它们长期相处后出现的新行为。
