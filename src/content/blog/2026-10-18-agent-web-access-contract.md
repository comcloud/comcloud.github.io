我怀疑，个人 Agent 下一道难关并不在模型能力，而在互联网愿不愿意承认它有权代表一个真实用户。哪怕模型能把任务推理得很完整，只要服务方拒绝它进入，所谓替你办事就会停在登录页。

10 月 17 日，《The Verge》发布了一篇关于网站阻挡 AI Agent 的集中调查。文中涉及订票、电商、金融账户和点评服务。这里的日期应当说清楚：当天发布的是对近期现象的梳理，不是所有限制都在那天开始实行。

## 会用浏览器，并不代表有代理权限

一种常见说法是，只要 Computer Use 足够成熟，Agent 就能代替人做所有网页操作。我认为这漏掉了身份与委托关系。网站看到真人登录，通常认为操作出自账号持有人；看到自动程序，则必须区分用户授权、违规代理和恶意冒用。

如果 Agent 点击了“确认支付”，谁能证明这个动作在授权范围内？用户是否同意金额？授权是否已到期？商家能否识别这是谁的 Agent？这些不是再优化鼠标坐标就能解决的问题。

因此，真正的产品难点可能是一份可验证的代理授权记录：由谁委托，允许执行什么，在哪些网站、哪个时间段、什么金额范围内有效，何时必须要求人工确认。它还需要可撤销的权限和争议后的操作证据。否则模型再聪明，商业服务仍有理由将其视为高风险流量。

## 阻挡 Agent，并非只有平台利益这一种解释

有人把网站的限制全部归结为平台害怕失去广告收入。这可能是部分原因，却无法解释所有场景。搜索爬虫只是读取信息，订票 Agent 会锁定库存，支付 Agent 会转移资金，账户 Agent 还可能接触敏感数据。网站为此做额外风控，并不奇怪。

Cloudflare 2026 年 7 月介绍过更细的 AI 流量管理思路，将搜索、Agent 与模型训练类爬虫区分开来。这个方向至少承认了一个事实：不能把所有自动访问看成同一种行为。但是，识别访问用途仍然不足以验证某次交易背后的用户同意。

Shopify 提供了另一种路线。它在 2026 年推进 Agentic Storefronts 和相关开放商业协议，希望让商品发现、购物车与结账有明确的机器接口。与其要求 Agent 悄悄模拟人的浏览器，不如让服务方明确提供受控的代理交易入口。

## 我担心第二层影响是入口集中

假如越来越多网站只接受经过认证的 Agent，能够完成商业合作、身份认证和支付对接的平台就会得到更大优势。小型开发者即使模型更好，未必拥有进入主流服务的资格。

但全面放开也不自动意味着对用户更好。一个能横跨账号、支付和消息系统的代理如果受到恶意网页内容干扰，后果会落到现实生活里。真正的取舍不是开放与封闭二选一，而是允许可核验的委托，同时把执行范围严格限制在用户授权之内。

我也可能判断错。如果基于用户现有浏览器会话的代理技术足够可靠，网站或许能直接接受，无需另建一套行业凭证。另一种可能是商业利益倒逼开放：只要 Agent 带来的成交额明显增加，商家自然会放松限制。

下一步我想检验这个判断，而不是继续争论。选取十个订票、购物、查询任务，分别让人工用户、通用浏览器 Agent 和官方合作接口执行，逐项记录失败原因、授权次数、完成率与投诉处理方式。只有把“模型不会做”和“网站不允许做”分开，才可能知道这门生意真正卡在哪里。
