多智能体系统最危险的失误，可能不是某个模型答错，而是一群模型共同认定了错误的评判标准。只要真正的结果无法及时检验，增加 Agent 数量就可能让系统更自信，却离正确答案更远。

## 一、Agent 数量增加，为什么成绩可能下降

**资料给出的事实：** 2026 年 11 月 20 日，独立评测机构 METR 发布了一份关于前沿模型研究能力的长篇报告。附录中的多智能体实验，比较了共享讨论空间的 Agent 群体与花费相近总 token 的独立并行尝试（best-of-k）。在能够频繁获得准确评分、工作可以拆开再组合的 nanoGPT 优化任务上，群体协作表现出较稳定的收益。

但另外两类任务给出了不同结果：Minecraft Bot 和 Train a Program 都有明确的最终评分，只是评分依赖隐藏环境或隐藏测试样本，Agent 无法即时看到真正结果。在部分实验里，群体表现比独立尝试更差；Train a Program 的一些配置中，群体越大，成绩反而越低。METR 观察到，Agent 会围绕自己构造的测试集不断优化，却很少重新质疑这个测试集是否代表真实目标。群体规模扩大时，自测表现与隐藏测试表现的差距也会扩大。

这组现象更有意思的地方在于：**问题不一定出在协作失败，而可能出在协作太成功。**大家快速交流、借用彼此的发现、整合方案；然而，如果最先被传播的是一个偏掉的目标，后续每轮迭代都可能把偏差放大。

**我的推断：** 多智能体系统的收益，首先取决于反馈质量，其次才是团队人数。协作能够加快寻找答案的速度，但无法自动保证大家寻找的是正确答案。

## 二、十个模型互相审查，不等于十份独立证据

一种流行解释认为，多 Agent 的优势在于彼此监督：一个负责写，另一个负责审，第三个负责反驳。这个解释有时成立，却忽略了判断错误的相关性。

Anthropic 在 2026 年 8 月关于多智能体行为的研究中发现，相同或相近模型在相似条件下，常会作出相似选择。共享论坛让知识传得更快，也能让未经核实的假设更快成为共同前提。其实验中，模型的协作形态、角色分配和任务依赖关系显著影响结果；独立搜寻与互相依赖的工程任务并不能用一种组织方式解决。

再看 METR 报告中的另一项发现：当模型负责判断更强或相近模型产出的评测任务是否有价值时，部分模型评分高于人类专家。报告举例，表现最接近人类评分的 Opus 5.5 评审，对 Astra 产出的任务平均比专家高出约 0.2 分（满分 1 分）。这并不能证明所有 AI 评审都会高估强模型，却表明“另找一个 AI 评价”不天然等于独立验证。

**我的推断：** 如果起草、优化、评审使用相似知识、相似偏好与同一份测试数据，多 Agent 可能只是在重复一次判断。增加角色称谓不会增加多少证据；真正宝贵的是独立的信息来源、不同的失败假设和能够推翻当前方案的外部测试。

这一点也能从人机协作中得到侧面提醒。Anthropic 2026 年 10 月的受控实验让专业分析师与带有随机倾向的 Agent 合作。使用 Agent 的 50 名分析师，在四项分析选择上总体有 86% 的选择与 Agent 倾向一致。研究设计刻意增强了 Agent 的立场，不能据此推断日常工作中的普遍服从率，但说明“有人签字”也未必意味着有人作出了独立判断。

## 三、真正昂贵的资源，可能是高质量的验证机会

为什么开发者偏爱自动评分、单元测试和可重复运行的模拟环境？原因很现实：机器可以低成本、高频率地获得反馈。若每次评价都需要现场试运行、领域专家复核或数周后才能见到结果，最容易规模化的训练与测试方法就会失去优势。

METR 为此提出一个近似指标：建立任务环境、重复运行和评分所需的生命周期成本。在其任务集合里，控制完成任务所需的人类时间后，评分和搭建成本较高的任务通常更难让模型做好。这只是相关性，不代表验证成本直接导致模型能力不足；METR 自己也指出指标粗糙、任务范围有限。

**我的推断：** 企业部署 Agent 时，最先需要估算的可能不是每次调用多少 token，而是一次真实可靠的验证值多少钱。

比如工业视觉，离线样本里识别得很好，并不等于换一批设备、料架、光照或物料后仍然可靠；招聘筛选，简历匹配得分很高，也不等于被筛选的人后来表现更好。两者的共同陷阱是：团队可能不断优化眼前最便宜的代理指标，却把跨场景错误或长期损失留到上线以后才发现。

因此，一个合理的系统设计应把“探索预算”和“验证预算”分开。让多个 Agent 并行提出方案可以很便宜，但必须保留不可见的测试样本、跨场景复验、人工专家异议以及撤回方案的权限。对于真实答案暂时不可知的任务，输出“尚未证实”有时比继续组织讨论更有价值。

## 四、风险在哪：这个判断也可能被新证据推翻

**仍然不确定的部分：** METR 研究的是一组特定评测任务，群体实验的规模和配置并不完全均衡。报告也明确指出，提示词、团队组织形式和模型差异都会改变结果。某些隐藏评分任务一旦获得更好的外部验证工具，多 Agent 可能重新取得优势。因此不能推出“多智能体普遍不如单智能体”，更不能把当前实验结果当作永久规律。

还有一种反驳很有力：真正的企业工作并非没有反馈，只是反馈慢。如果系统可以建立可靠的延迟评价机制，并让不同模型分别独立提出反例，协作也许能够显著减少错误。我的判断会在以下证据出现时被削弱：在匹配 token、计算时间、工具权限的条件下，多 Agent 能跨多个隐藏测试分布、连续多个真实业务周期，稳定胜过独立并行方案；而且收益不是靠额外人工兜底换来的。

所以这里值得警惕的不是“协作”本身，而是未经验证的共同信念被误认成共识。AI 团队讨论得再充分，也不应替代真实世界的检验。

## 下一步去查什么

我会优先寻找三类证据：第一，公开多 Agent 实验里，有多少采用同等成本的独立尝试作为对照；第二，模型群体在隐藏样本、跨场景数据上的性能是否随着人数变化；第三，实际企业任务中，外部测试、专家审查和错误恢复分别花费多少时间与金钱。若有条件做小实验，最有解释力的不是比较一名 Agent 和十名 Agent，而是固定预算，比较“共享讨论”“独立并行”“独立并行后由外部验证器裁决”三种流程。

当评价标准本身可能错时，先提高验证质量，再谈增加多少智能体。
