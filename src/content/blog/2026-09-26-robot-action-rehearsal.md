我现在更看好一种介于“大模型只做高层规划”和“VLA 直接输出动作”之间的路线：让大模型先在一个可视化的动作空间里排练，再决定哪些动作真的交给机器人执行。对物理系统来说，可编辑的动作提案可能比一次性生成最终控制量更重要。

技术圈很容易把机器人模型竞争理解成一条单线：模型越大、机器人数据越多、端到端训练越彻底，最终就会从语言和图像直接得到可靠动作。我对这个结论越来越保留。现实机器人最麻烦的地方，往往不是不知道任务目标，而是最后几厘米的接触、视角变化、碰撞约束和误差修正。一个模型“理解应该把杯子放到托盘里”，距离机械臂真的安全完成动作，中间还有一整层执行问题。

9 月 24 日提交的 World Action Agent（WAA）提供了一个很好的观察窗口。它没有让 VLM 直接吐出最终轨迹，而是给模型一个 visual action workspace。系统会自动从场景几何里选择接触视角；每个动作先变成一个可以修改的 proposal，由主 Agent 或 Imagination Agent 预览、根据反馈调整，然后再执行；真正执行后，还会在当前视角里做残差修正。换句话说，动作先成为“可以看、可以改、可以否决”的中间对象。

论文报告，在 LIBERO-Pro 上，WAA 使用从 LIBERO-90 演化出的技能达到 75.6% 平均成功率；同一套技能还能迁移到 robosuite。更有意思的是，作者把 WAA 运行产生的 interaction traces 反过来用于训练更小的 Qwen3.5-9B，报告其域外成功率从 1.7% 提升到 43.3%。这些结果还只是工作中的论文，不能当成机器人通用能力已经被证明，但它提示了一种很有产品感的路径：大模型负责在结构化工作区里做高成本推理，系统把好的执行轨迹沉淀下来，再训练更轻的模型承担更多日常控制。

一周前的 SafeHarness 也从另一个方向支持这个判断。那篇工作里，coding agent 在推理文本中明明知道障碍物存在，prompt 也明确要求不能碰，但机器人仍会规划出碰撞路径。问题不是“模型没有读懂规则”，而是规则没有变成执行前必须通过的机器约束。SafeHarness 因此把路线规划、碰撞验证和接触选择放到语言模型之外。作者报告，在其 SafeLIBERO 设置下，任务成功率和避碰率都明显提升。

这两项工作不是同一个系统，也不能直接横向比较，但它们共同指向一个变化：机器人里的大模型也许不应该拥有“一步到执行器”的特权。更现实的接口是，大模型提出候选，环境给出可视化或几何反馈，验证器检查风险，低层控制器处理精确动作，必要时重新排练。这里真正变得重要的不是某个单一 VLM，而是整个动作工作区的设计。

为什么是现在？因为通用 VLM 的空间理解和任务分解已经足够强，能够参与机器人操作，但它们的精度、实时性和稳定性又还没有强到可以忽略传统几何和控制。这恰好给“中间表示”留下空间。过去大家会把这层看成工程胶水；现在它可能反过来成为系统的核心资产，因为它同时承载安全规则、技能、验证结果和训练数据。

这个结构还有一个二阶影响：机器人公司的数据优势可能从“积累多少原始示教”转向“积累多少高质量动作提案、失败原因、修正过程和最终执行结果”。直接记录一次成功轨迹，只告诉模型答案是什么；记录一次排练和修正，则保留了“为什么原方案不行、哪一步被改、什么反馈起作用”。对训练下一代小模型，这种数据可能比单纯动作序列更有信息密度。

## 风险在哪，我可能错在哪

最直接的风险是延迟。机器人控制不是写代码，动作提案、视觉预览、多 Agent 讨论、再验证，每增加一层都会消耗时间。对于高速抓取、动态避障或工业节拍严格的任务，这套方式可能根本来不及。更可能的落地形态，是高层或关键节点才用排练，低层连续控制仍由快速策略完成。

第二，WAA 目前是 working in progress，主要结果来自 LIBERO-Pro、robosuite 等基准。真实工厂里的标定误差、柔性物体、遮挡、工具磨损和接触力，比桌面操作复杂得多。SafeHarness 也有明确的简化条件。把两篇论文外推成“机器人都应该采用这种架构”还太早。

什么证据会推翻我的判断？如果同样的视觉主干、同样的训练数据下，端到端 VLA 在真实接触任务里持续取得更低延迟、更低碰撞率和更强域外泛化，而且不需要外部动作排练和验证，那么中间工作区可能只是当前模型能力不足时的过渡方案。

下一步我最想查的是一个很朴素的对照实验：同一个机器人、同一个 VLM backbone、同一批任务和示教数据，一组直接输出动作，一组使用 visual rehearsal + verifier；不要只看成功率，同时记录决策延迟、碰撞、人工接管、失败恢复次数和单位任务计算成本。谁能在真实环境里把这些指标同时做好，才更接近可用的机器人智能。
