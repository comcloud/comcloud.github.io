开源 Agent 如果能做成一家大公司，卖的很可能不是那份可以免费下载的代码，而是组织愿意长期托付给它的执行能力。Nous Research 在 10 月 7 日确认完成 9000 万美元 B 轮融资，TechCrunch 报道其估值为 15 亿美元，同时宣布向企业客户推出 Hermes for Businesses。我觉得，这比融资数字本身更值得讨论。

Nous 的公开说明称，Hermes Agent 今年 2 月以 MIT 许可证开放，代码已被克隆超过 2400 万次，按公司内部估算约占全球 AI token 使用量的 2.5%。这些数字很醒目，但必须小心：克隆次数不等于独立用户，更不等于付费企业；全球 token 占比也属于厂商估算，并非我能独立核实的市场统计。真正有商业意义的是，它正尝试把开发者的自发采用转化为企业采购。

## 开源负责扩散，企业付费负责降低责任成本

过去企业买软件，采购部门比较容易理解：买许可证、买账号、买功能。Agent 不一样。它会访问文件、调用模型、修改业务系统，还会把一次任务拆成多步执行。哪怕原始代码完全免费，部署它的人仍然要承担权限配置、日志留存、数据泄露、失败回滚以及模型成本波动。

所以我怀疑未来企业 Agent 的核心定价单位未必是每个用户每月多少美元，也可能是受治理的任务量、可连接的业务系统、企业级服务等级，以及对风险和成本的承诺。

这条商业路线和典型开源数据库、容器平台有相似之处：技术基础免费，企业为稳定运行、升级、集成和可追责付费。但 Agent 还有一个新问题：软件可以按设计执行，Agent 在同一任务里可能采取不同路径。商业客户要的不是「它偶尔非常聪明」，而是「它的失败能被发现、解释和控制」。

## 多模型选择，可能是有吸引力但不好兑现的承诺

Nous 在官方文章里把「用户自己选择 Agent 运行位置和底层模型」当成核心主张，并表示企业版本会帮助客户按任务选择更合适的模型与价格。这里面有真实的商业诉求：企业并不希望今天在一家模型厂商的产品里配置好全部流程，明天为了价格或合规又要重新做集成。

假如企业掌握的是相对独立的 Agent 工作流、记忆与工具接口，底层模型就有机会被替换，云服务商的定价能力也会受到一定约束。但替换并不免费。不同模型在工具调用格式、长任务可靠性、上下文习惯和安全策略上差异很大，实际换模型往往要重新评测。如果每次切换都造成一轮人工调试，「模型自由」就容易停留在销售话术。

因此，真正值钱的产品不只是提供模型下拉菜单，而是帮企业建立任务回归测试、成本—成功率对照、失败案例库和可追溯的执行环境。谁能把替换成本真正降下来，谁才能把开放性转化为可出售的服务。

## 平台合作也可能改变开源 Agent 的分销方式

这里有一个特别有意思的交叉信号。微软在 10 月 7 日宣布 Windows 上的 Microsoft Execution Containers 正式可用，列出的未来集成伙伴就包括 Hermes Agent。对 Nous 而言，这说明第三方 Agent 不一定必须自己重建操作系统级隔离能力；它可以借平台能力降低一部分部署成本，转而把精力放在组织记忆、任务质量和企业服务上。

但交换条件也很明显：如果身份、权限、设备分发和安全合规都掌握在操作系统或大型企业软件平台手里，独立 Agent 公司将依赖这些平台提供的接口与认证。平台可以帮助它获客，也可能逐渐控制客户关系。开发者喜欢哪个 Agent，和采购部门最终批准哪个 Agent，不必然是一回事。

我认为这会产生两种不同的公司。一种拥有大量社区用户，却很难进入生产系统；另一种用户声量不高，却因为治理、实施和行业接口拿到稳定合同。前者可能成为流量入口，后者才更像传统意义上收入可持续的企业软件商。

## 我可能错在哪

最直接的反对意见是，开源社区可能很快复制企业付费层的大部分能力。特别是大型客户拥有足够强的内部平台团队时，它们可以自己部署 Hermes，再搭建审计、权限和模型路由，并不需要多付订阅费。

另一个风险是商业模式被平台直接压缩。Windows、云厂商和大型 SaaS 可能把通用 Agent 运行、安全与管理能力作为基础服务打包出售，留给独立供应商的只剩行业场景与深度集成。届时 15 亿美元估值对应的不是今天的软件收入，而是投资者对未来客户迁移的押注。现有公开材料还不能证明这种迁移已经完成。

我接下来最想调查的，是 Hermes for Businesses 的真实收费方式、付费客户留存、部署后的单位任务成本，以及企业采用开源 Agent 时最难通过的安全与采购环节。如果这些数据能够显示客户愿意持续为运行质量和治理付费，那么开源 Agent 的商业故事才算从社区热度走到了组织预算里。
