我觉得 Agent 市场正在遇到一个计价上的错位：模型按 Token 收费，客户真正购买的却是完成的工作。一个答案生成得便宜，不代表一项工程任务做得便宜。

10 月 17 日，DeepSeek 推出 V4.1-Flash-1017。这是 9 月版本的更新，不是新架构首发。官方表示新版本在编程和 Agent 类任务上有进步，而且回答更短、任务执行更快；API 名称和价格保持不变，权重已以 MIT 许可证开放。

## 为什么 Token 单价不够了

按 DeepSeek 提供的数据，Terminal-Bench 4.0 由 31.2 上升到 42.3，DeepSWE v1.1 由 74.2 升至 77.0。看起来不错，但这些是厂商根据指定测试条件公布的结果，并不是独立机构在生产场景复核后的结论。

我更关心的是一项任务从开始到被验证完成的总代价。一次对话结束就是一次输出；Agent 却可能为了修复一处代码，连续读取文件、修改代码、调用测试、回退，再重新执行。少输出两千个 Token，如果导致一次额外失败，节省下来的费用可能马上消失。反过来，多花一次推理成本，避免后续十次工具调用，也可能更划算。

因此评判 Agent，应该把成功率、平均重试次数、工具费用、耗时和人工接管成本放在一起看。每百万 Token 的价格只是原材料价格，不是交付成本。

## 模型能力和运行框架被绑得更紧了

DeepSeek 公告说明，不同基准使用不同的 Agent 运行框架，例如 Claude Code 和 Mini-SWE-V2，同时建议开发者更新自己的 Harness。这里面有个重要事实：同样一套模型权重，放入不同工具系统里，结果可能变化很大。

运行框架会决定什么时候调用工具、保留哪些上下文、怎样检测失败、是否重试。模型能产生正确的下一步，并不代表整个系统能走到正确结果。企业评估工具时如果只比模型排行榜，往往会把这些隐性成本漏掉。

## 无感升级并非没有代价

这次 API 模型名不变，是开发者的便利，也是部署管理的考验。行为更积极、回答更短，在多数场景可能改善效率，但也可能让原先依赖固定输出格式或推理步骤的业务产生偏差。

开源权重同样需要分开看：可获得源权重是一回事，低成本在本地稳定运行是另一回事。大规模模型还需要推理框架、算力、存储和维护工作，不能因为许可证开放就把部署费用按零计算。

## 我可能错在哪

我可能高估了任务级计价的价值。当工作负载足够标准化、框架差异缩小后，Token 消耗也许能很好地预测最终费用。另一种可能是，本次改进主要集中于厂商选择的基准，应用到真实仓库后没有类似效果。没有同等预算的独立对照，现在还不宜下定论。

任务级指标本身也能被包装。只选容易的任务、排除失败任务、隐瞒人工帮助，任何模型都能展示漂亮的平均成本。统计里必须包含失败、重试和验证费用。

下一步我想自己做一项可复核的小实验：选择二十个带自动测试的真实代码问题，固定执行框架、工具权限与重试上限，对比新旧模型多次运行后的成功率、任务总账单和用时。只有这组结果出来，我才会相信“更便宜”意味着什么。
