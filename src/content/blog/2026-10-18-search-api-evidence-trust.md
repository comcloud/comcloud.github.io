我觉得，Agent 时代有一种权力被低估了：决定模型最先看见哪些网页。一个模型可以善于推理，但如果它拿到的检索结果已经偏斜，后面的推理再流畅，也可能只是在错误材料上完成漂亮的工作。

10 月 17 日，DeepSeek 开放了自研 Search 与 Fetch API。官方发布页说明，两类调用分别用于网页搜索和抓取，每千次请求收费 0.75 美元；在指定的 Agent 工具中暂时提供免费调用，计划从 10 月 31 日 16:00 UTC 开始计费。这是开发者接口开放的日期，不代表其搜索引擎在当天才出现。

## 降低接入成本，会改变默认的信息来源

过去给 Agent 接入实时信息，往往要采购一套搜索服务，再接一个页面抓取或解析工具，然后由模型处理返回的数据。对于个人开发者，这确实是麻烦事。现在模型供应商把搜索、抓取和推理放在同一套 API 里，调用更容易统一，出错时也可能更方便排查。

但便利有一个隐性代价：当开发者不再主动选择搜索源，默认搜索接口就开始决定 Agent 看到的事实候选。结果排序、收录范围、更新时间、网页重复内容识别，都会影响最终输出。用户看到的是模型的一句话，却不知道前面有哪些资料根本没有进入模型上下文。

这不意味着自研搜索一定比第三方差。真正的问题是我们缺少一套清楚的方法，判断不同搜索接口给出的证据是否可靠。

## 检索并不等于事实核验

技术圈容易把 RAG 或联网搜索描述成解决模型幻觉的办法。我认为这个说法太省事了。搜索结果来自真实网站，也可能只是转载未经证实的传闻；多个结果看似相互印证，却可能引用同一个错误源头。网页正文还可能混入试图改变 Agent 行为的指令。

Fetch 只是把网页内容交给模型，不意味着内容已经得到认证。一个正确设计的 Agent 应该把外部网页视为证据候选，而不是系统命令。它还需要保存抓取时间、原始链接、引用段落和搜索条件，在涉及高风险结论时回到原始材料验证。

这对工业视觉和科研工作也一样重要。假设 Agent 查到某相机的标定精度、某开源模型的延迟，或某篇论文的实验成绩，它不能只引用二手总结。设备参数要回到厂家文档，论文成绩要检查版本与实验条件，否则一个错误数字就可能被后续设计放大。

## 搜索平台也面临内容访问权问题

Cloudflare 在 2026 年 7 月曾讨论对搜索、Agent、训练三种不同 AI 流量提供细分管理。同年 10 月 17 日，《The Verge》又集中报道了一些网站阻挡 AI Agent 的情况。后者是新发表的调查梳理，不代表报道涉及的每项限制都在当天新发生。

这里出现了一个矛盾：模型供应商希望 Agent 能随时取得更多网页信息，网站却有理由在授权、安全、流量收益之间设定访问条件。因此，搜索 API 的价格只是显性成本；稳定获得合法、及时、可追溯的内容，可能才是长期成本。

如果这条判断成立，未来会有一类新服务专门解决证据管理：保存原始网页版本、交叉核对引用、识别来源之间的转载关系、把原始材料和模型结论对应起来。它未必拥有最大的模型，却可能在企业和科研场景具有明确价值。

## 我可能错在哪

也许搜索和推理一体化反而更能改善质量。模型厂商掌握完整链路后，可以统一减少重复内容、处理时效和检测低质页面；独立搜索服务同样可能存在商业偏向。不能把“不同供应商”误当成“独立事实来源”。

我也不知道 DeepSeek 新接口的实际覆盖率、引文正确率和抗提示注入表现。目前缺少充分的独立测试，不能仅靠定价和厂商描述下结论。

下一步我想做一项可复制的小测试：抽取一百个有公开原始资料的问题，覆盖论文版本、公司发布、设备参数和政策文档。用 DeepSeek Search / Fetch 与另外两套检索服务独立取回结果，比较首条正确率、原始出处可追溯性、日期误判率，以及模型引用了不存在来源的次数。把差异找出来，才知道便宜的搜索究竟省下了什么。
